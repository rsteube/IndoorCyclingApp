Surface 1 · Android

The Android app

Kotlin Multiplatform · Jetpack Compose · Material 3 API 26+ Runs on any Android - no Google services

The headline screen - live ride HUD

Arms-length legibility on a sweaty phone. Zone-aware target watts, cadence, HR, ERG-mode lock indicator, and the next interval on deck. Designed to be readable from the saddle, not from the desk.

ERG mode

Targets the trainer with FTMS opcode 0x05; auto-requests control on connect.

Wall-clock timing

Elapsed time anchored to now - phaseStart so a hiccupy dispatcher can't drift the ride.

HR fallback chain

Dedicated BLE HRM preferred; falls back to trainer-reported HR if the strap drops.

±difficulty stepper

Multiplicative bias on target watts. Optional Zwift Click v1 hits the same code path.

Skip / Pause

Phase anchor resets on every transition so segment progress stays honest.

Foreground service

connectedDevice FGS + 4-hour wakelock so BLE keeps flowing when the screen sleeps.

Rides tab

Workout library

Filter chips derived from the loaded workouts (no hardcoded categories). Each card shows the zone profile, duration, TSS and IF. A connection-state strip at the top doubles as the "Pair a trainer" nudge until any device is paired.

First-run

"Start here" pinned card

An ember-bordered "START HERE · YOUR FIRST RIDE" card pinned to the top of the Rides tab on a fresh install - points at a 15-minute mixed-zone starter workout. Disappears after the first completed ride; the workout is filtered out of the regular list while pinned to avoid duplication.

Workout detail

Step preview

Truncated to 6 steps with a "tap to expand" pill. Bottom CTA is state-aware: "Pair a trainer to ride" if no trainer is connected.

Pairing

BLE scanner

Live "Scanning · N found" state with an Open-Settings escape hatch. Includes a Use Mock Trainer button for users without hardware.

Workout library

Import paths

Four import paths into one pipeline: file picker, share-target intent, content:// open, and indoorbike://import deep links - including QR.

Community libraries

Browse community repos

The site serves a registry index that surfaces curated community packs in a "Browse community" section. Tap a card to open the remote-repo browser, then pick the individual workouts you want - each becomes a static local copy under your imports. No accounts, no recurring sync.

History tab

Week-grouped rides

Totals card at the top (rides / time / kJ). Tapping a session opens its post-ride overview with the chart and KPIs.

Progress tab

Streak & rider level

Streaks, 14-day mini-grid, rider-level meter (XP = watt-minutes / kg) and badge grid. All computed locally - no backend.

Post-ride

Ride overview

NP, IF, TSS and kJ across the top, then a power-adherence chart overlaying your actual power line on the planned zone bars so you can see where you held the target and where you didn't. Time-in-zone breakdown and tag inference all computed in the shared module.

Post-ride · Share

1080×1080 share card

A square share image rendered from a Compose GraphicsLayer: header, three KPI tiles, the power chart, and a "toughest interval" callout (longest Z4+ segment, falls back to peak-power for unstructured rides). Save to Pictures/Indoor Bike via MediaStore, or hand to the system share sheet via FileProvider - all without third-party deps.

Settings · Profile

FTP & weight

IME-Done / focus-loss commit, validated against MIN/MAX bounds. Persisted to DataStore.

Settings · Devices

Trainer · HRM · Controller

Single grouped card with state-aware Pair / Disconnect / Forget actions in a bottom sheet, keeping the destructive option out of the always-visible scroll.

Settings · Cloud

Intervals.icu opt-in

Athlete ID + API key (with show/hide eye), auto-upload toggle disabled until both fields are filled. The privacy posture is stated explicitly in the copy.

Pre-ride

Countdown ready

The HUD pre-warms with the upcoming target before the timer starts so you're not staring at zeros mid-stand-up.

Plus - under the hood

KMM

Shared core

Workouts, BLE wire formats, FIT writer, progression math - all in commonMain. Android-first, iOS deferred.

BLE

Three peripherals

Trainer (FTMS / Cycling Power), HRM (with name-heuristic for Garmin HRM-Pro), and Zwift Click v1 controller. All independent, all auto-reconnect.

FIT

Hand-rolled writer

14-byte header, nibble-table CRC-16, definition + data messages, lap-per-segment. Round-tripped against a synthetic 30-min ride in tests.

QR

Camera-X scanner

ZXing decode of https://indoorbike.app/share/#w=… or indoorbike://import. URL-safe base64 JSON decoded locally - no fetch required.

⌥

Repositories & registry

Two-source library: bundled JSON plus user-imported files. The remote-repo browser fetches manifests on demand and the rider picks individual workouts to keep - each saved as a static local copy. A versioned registry index at indoorbike.app/registry.json drives the Browse-community list - auto-discovered when published, no app update needed.

DB

SQLDelight + DataStore

Sessions + 1Hz telemetry in SQLite (cascade delete on session). FTP, paired devices, intervals creds in DataStore Preferences.

UX

Soft onboarding

Two-step bottom sheet: profile (FTP + weight) and permissions rationale. Non-gating - dismissal still marks complete.

∆

Mock trainer

Debug-only ride mode with realistic power/cadence emulation so the app's testable without hardware. Gated behind BuildConfig.DEBUG.

⏻

Crash-recovery

Active session snapshotted to filesDir every 5s; atomic tmp+rename. Cleared on stop/complete. The "ride in progress" banner picks up where you left off.

∥

Side-by-side install

Debug and release builds get separate applicationIds, separate DataStore + DB, and a grayscale debug launcher icon. Develop and ride on the same device without stomping on your real history.

∑

Workout summary math

NP, IF, TSS, kJ and tag inference all live in shared (commonMain) so they're testable, deterministic, and reused by Android, the post-ride overview, and the share card. No platform-specific drift.

◷

Time in zone

Each ride's seconds-spent in Z1–Z7 derived from 1Hz telemetry - surfaced in the post-ride overview and aggregated across the Progress tab.

↔

Dedicated pairing screens

Trainer, HRM, and Zwift Click each get their own scan flow with the same UX shape: live "Scanning · N found", filter heuristics tuned per device class, and a permission-denied escape hatch to system Settings.

Surface 2 · Web

Browser workout editor

Vanilla HTML / CSS / JS No backend, no account Sends to phone via QR or deep link
7

Zone palette

Drag or tap to add Z1 Recovery through Z7 Neuro tiles. Plus a "Free" tile for unstructured intervals.

⌘

Direct manipulation

Click to select, Ctrl/⌘ + Click to multi-toggle, Shift+Click to range-select, Alt-drag to duplicate, Del to delete, arrows to nudge power and duration.

≣

Set builder

"+ Interval set…" lets you build N × on/off blocks (10×30/30, 4×8 threshold) without dragging individual clips.

Σ

Live stats

Duration, TSS, IF, average %FTP, peak %FTP and kJ all recompute as you edit. The same FTP-aware math the app uses.

↓

JSON download

Same on-disk schema the app reads. Drop the file into the workouts directory or share-target it into the app.

QR

Send to phone

Embeds the full workout as URL-safe base64 in indoorbike.app/share/#w=…. Phone scans the QR and the workout decodes locally - no server fetch.
